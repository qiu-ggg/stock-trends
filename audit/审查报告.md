## 二、代码架构审查

### 2.1 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | 原生 HTML/CSS/ES5+ 风格 JS（IIFE 封装，无构建、无框架、无依赖） | `index.html` + `style.css` + `script.js` |

## 三、问题清单

> 格式：**严重程度｜文件:行号｜问题描述｜复现步骤｜最小修复方案**

### 🔴 致命

#### #1｜致命｜`data.js:490-492, 547`
**问题**：抓取失败导致热点池为空时，仍把空对象写回 localStorage，**覆盖历史热度基线**。链路上游 `fetchAllFeeds (466)` 用 `.catch(() => [])` 静默吞掉全部失败，因此"9 个请求全挂"会稳定触发本缺陷。

**复现（T2）**：
1. `computeHotItems([茅台, 宁德])` → `stock-last-hot` 存入 2 个关键词 ✅
2. 网络抖动，`computeHotItems([])`（空池）→ **基线被覆盖为 `{}`** ❌
3. 恢复后再算，`delta` 只能走哈希伪造路径

**最小修复**（1 行）：
```js
// data.js:547 之前
if (Object.keys(current).length) saveLastHot(current);
```

#### #2｜致命｜`data.js:493-497, 529-530`
**问题**：无历史基线时调用 `simulateDelta()`，**用关键词哈希生成伪随机数并当作真实涨跌幅展示**。用户在热搜榜看到 `+20%` 会认为是真实热度变化，实际与行情无关；且因 #1 的存在，基线极易丢失 → 该伪造值会频繁出现。代码与界面均无"模拟值"标注。

**复现（T2 第 3 步）**：基线丢失后首位 `delta=20`，该值由 `keyword.charCodeAt` 哈希得出，与任何历史数据无关。

**最小修复**（1 行）：
```js
// data.js:530
else delta = null;      // 无基线即不展示变化率
```
前端无需改动：`script.js:56` 的 `deltaInfo` 已对 `null` 返回 `'—'`，会自动降级为占位符。

#### #3｜致命｜`data.js:1651, 1653-1666` + `data.js:1530-1531`
**问题**：自动画像下风控完全空转，且展示的止损位数学上不可能被触及。
- `data.js:1651`：`var L = (profile && profile.auto) ? {} : ...` → 自动画像时 `L` 为空对象
- 因此 `belowHard/belowStop/aboveT1/aboveT2`（1653-1656）恒为 `undefined`，**四个硬性风控分支永不执行**，动作只由 `composite` 评分决定
- 同时 `buildPlan` 用 `deriveLevels`（1502）派生价位，而 `deriveLevels` 的止损是 `P - atr*2.5`、硬止损 `P - atr*3.5`（1531）—— **以现价为锚**，所以"止损位"随价格同步平移
- 后果：计划卡片与 8 章报告会展示一个具体数字（如"止损 35.95 元"），但该数字每次刷新都变，且永远不可能被跨越；用户按此挂条件单会失效
- 影响面：画像库只有 3 只标的（000063/002422/000032），**其余全部股票都走自动画像路径**

**复现（T1a）**：同一形态下取三档价格 20/40/80 元，`(现价-止损)/ATR` 恒为 `2.5 / 2.5 / 2.5` —— 证明止损位是现价的固定倍数，而非固定风控位。

**最小修复**（不改判定逻辑，只补披露）：
```js
// data.js:1762 buildPlan 返回值中追加
levelsNote: ((!(profile && profile.auto) && (L.entry || L.stopLoss)))
  ? '' : '止损/目标位由 ATR 与关键位实时推导，随价格移动，仅作参考，不可作为固定挂单位',
```
并在 `renderPlanBox` / `buildReportMd` 中显示该提示。

#### #4｜致命｜`script.js:1409-1433`
**问题**：`fetchStockAnalysis` 无请求序号、无 `AbortController`，**先发起的慢响应会覆盖后发起的快响应**。用户连续搜索两只股票时，页面最终显示的是先搜的那只。

**复现（T7）**：桩设置"600519（茅台）延迟 300ms、000858（五粮液）延迟 30ms"；先搜茅台、10ms 后搜五粮液 → 输入框最终值为 `000858`，但 `#stock-quote` 渲染的是**贵州茅台**。

**最小修复**（约 3 行）：
```js
let stockReqSeq = 0;                                    // 模块级
async function fetchStockAnalysis() {
  const seq = ++stockReqSeq;                            // 进入即占号
  ...
  const data = await STOCK_DATA.analyzeStock(code);
  if (seq !== stockReqSeq) return;                      // 过期响应直接丢弃
  renderStockAnalysis(data);
```

#### #7｜严重｜`data.js:1536-1538`

#### #8｜严重｜`data.js:122-133`
**问题**：关键词模糊匹配有**三处越界**：
1. 单字符不设下限 → `"A"` 命中 `万科A(000002)`、`"中"` 命中 `中国中免(601888)`
2. 多义关键词静默取首个 → `"银行"` 返回 `招商银行(600036)`，用户无从得知还有工行/建行等
3. 结果取决于 `for...in` 的插入顺序，**不可复现**

**复现（T4）**：见上，`"银行"/"A"/"中"/"股份"` 均命中。

**最小修复**：

#### #9｜严重｜`data.js:466-477, 479-485`
**问题**：`fetchAllFeeds` / `fetchGubaByCode` 都用 `.catch(function () { return []; })` **静默吞掉所有抓取异常**。用户看到"暂无讨论内容"，无法区分"确实没内容"与"网络/接口全挂了"——属于典型的异常静默。

**复现**：T2 第 2 步即由此路径触发（空池无任何错误痕迹）。

**最小修复**：返回结构携带失败计数，渲染层据此区分空态与错误态：

### 🟡 中等

#### #10｜中｜`script.js:418-430, 450-456`
**问题**：自动刷新间隔只在 HTML 属性层约束（`index.html:238` 的 `min=5 max=3600`），**JS 层只校验 `n > 0`**，且 `loadConfig` 从 localStorage 读取时同样不校验下限。用户手输 `1`（或用 DevTools 改 localStorage）即可让定时器每 1 秒发一次请求 → 高频抓取、可能被目标站限流。

**最小修复**：
```js
const n = Number(seconds);
if (Number.isFinite(n) && n >= 5) {
  state.autoTimer = setInterval(function () { fetchHot(); fetchFeeds(); }, Math.min(n, 3600) * 1000);
}
```

#### #11｜中｜`data.js:1750-1760` 与 `1744-1749`
**问题**：`REDUCE` 与 `AVOID` 共用同一分支生成退出批次（1750），而 `adaptForNoPosition (1643)` 把 `REDUCE` 的 label 改成"建议减持/回避"却保留 `key='AVOID'`。结果是 `REDUCE` 与 `EXIT→AVOID` 两种语义在 action.key 上完全合并，下游无法区分"减仓"与"离场"。属分支重复/语义合并。

**最小修复**：`adaptForNoPosition` 中为无持仓场景新增独立 action 常量（如 `REDUCE_NP`），或至少保留原 key 供下游判断。

#### #12｜中｜`.itest.cjs:110-169`
**问题**：测试进程**跑完不退出**（实测 20 秒后仍存活），被 `script.js:425` 的 `setInterval` 与页面定时器句柄挂住。接入 CI 会直接卡死，退出码也无法反映结果。

**复现**：`node .itest.cjs` → 输出正常但进程常驻。

**最小修复**（末尾 1 行）：
```js
console.log('\n结论：' + (process.exitCode ? '存在失败项' : '全部通过'));
process.exit(process.exitCode || 0);
```

#### #13｜中｜`data.js:866`
**问题**：`pctChan` 被 `Math.max(-0.6, Math.min(1.6, pctChan))` 钳制后输出（866），但字段名与下游展示都不体现"已钳制"。当真实位置超出该范围时（如价格远在通道外），界面显示的是被截断后的值，属数据失真。

**最小修复**：钳制时旁路保留原始值，展示层注明"已越界"：
```js
pctChan: +clamped.toFixed(3), pctChanRaw: +pctChan.toFixed(3), pctChanClamped: clamped !== pctChan,
```

### 🔵 重构项（分支结构）

> 按映射规则给出：固定值离散判断→查表；不同对象不同行为→策略/多态；复杂组合→决策表；前置校验→卫语句；状态流转→状态机。

| # | 文件:行号 | 函数 | 问题 | 映射 | 改法 |
|---|---|---|---|---|---|
